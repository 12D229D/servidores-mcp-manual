Manual y Guía de Servidores MCP

Una referencia completa, interactiva y estructurada para entender, construir y consumir servidores MCP (Model Context Protocol) con tecnologías web nativas.

🎯 Objetivo de este Manual

Esta guía está diseñada tanto para desarrolladores que quieren integrar MCP en sus aplicaciones como para ingenieros que necesitan architectar sistemas distribuidos con hosts, clients y servers MCP. Todo el contenido está pensado para correr 100% en el cliente, sin exponer secretos.

Capítulo 01

Arquitectura MCP

Hosts, clients, servers; JSON-RPC 2.0; roles y responsabilidades.

1. Roles en MCP

Un sistema MCP consta de:

  • Host: proceso que inicia y gestiona el ciclo de vida del servidor.
  • Client: proceso que consume un servidor MCP.
  • Server: proceso que implementa herramientas (tools) y recursos (resources).

Implementa herramientas y recursos.

2. JSON-RPC 2.0

MCP usa JSON-RPC 2.0 para la comunicación entre hosts, clients y servers. Los mensajes tienen la siguiente estructura:

JSON-RPC 2.0 
{
    "jsonrpc": "2.0",
    "method": "tools/list",
    "params": {
        "filter": {
            "type": "function"
        }
    },
    "id": 1
}

Capítulo 02

Transporte

stdio, SSE (HTTP+POST deprecated), Streamable HTTP; cuándo usar cada uno.

1. Tipos de Transporte

MCP soporta tres tipos de transporte:

  • stdio: Comunicación a través de stdin/stdout (útil para scripts y procesos locales).
  • SSE: Server-Sent Events (para streaming unidireccional).
  • Streamable HTTP: HTTP con cuerpo streamable (para request/response).

2. Cuándo Usar Cada Transporte

  • stdio: Ideal para integración con scripts y herramientas de línea de comandos. Riesgo: No exponer servidores stdio a internet.
  • SSE: Perfecto para streaming de datos desde el servidor al cliente.
  • Streamable HTTP: Usado para request/response tradicionales.

Capítulo 03

Ciclo de Vida

initialize → initialized → operation (request/response, notif., sampling) → exit.

1. Fases del Ciclo de Vida

El ciclo de vida de un servidor MCP consta de cuatro fases:

  • initialize: Inicialización del servidor.
  • initialized: Servidor listo para recibir solicitudes.
  • operation: Procesamiento de solicitudes (request/response, notif., sampling).
  • exit: Finalización del servidor.

Capítulo 04

Tools, Resources & Prompts

Esquemas, ejemplos JSON-RPC de list/call/get.

1. Tools

Las herramientas (tools) son funciones que un servidor MCP puede exponer a los clientes. Ejemplo de solicitud para listar herramientas:

JSON-RPC 2.0 
{
    "jsonrpc": "2.0",
    "method": "tools/list",
    "params": {
        "filter": {
            "type": "function"
        }
    },
    "id": 1
}

2. Resources

Los recursos (resources) son datos que un servidor MCP puede exponer a los clientes. Ejemplo de solicitud para listar recursos:

JSON-RPC 2.0 
{
    "jsonrpc": "2.0",
    "method": "resources/list",
    "params": {
        "filter": {
            "type": "dataset"
        }
    },
    "id": 1
}

3. Prompts

Los prompts son plantillas que un servidor MCP puede exponer a los clientes. Ejemplo de solicitud para obtener un prompt:

JSON-RPC 2.0 
{
    "jsonrpc": "2.0",
    "method": "prompts/get",
    "params": {
        "name": "default"
    },
    "id": 1
}

Capítulo 05

Construir un Servidor MCP

Estructura mínima (pseudocódigo Multi-SDK), registro de tools.

1. Estructura Mínima de un Servidor MCP

Un servidor MCP mínimo debe implementar las siguientes funciones:

  • initialize: Inicialización del servidor.
  • tools/list: Listar herramientas disponibles.
  • tools/call: Invocar una herramienta.
  • exit: Finalización del servidor.
Pseudocódigo Multi-SDK 
// Inicialización del servidor
function initialize() {
    // Configuración inicial
    registerTools();
}

// Registro de herramientas
function registerTools() {
    tools.register({
        name: "ejemplo",
        description: "Herramienta de ejemplo",
        parameters: {
            type: "object",
            properties: {
                input: { type: "string" }
            }
        }
    });
}

// Listar herramientas
function toolsList(params) {
    return tools.list(params.filter);
}

// Invocar una herramienta
function toolsCall(params) {
    return tools.call(params.name, params.arguments);
}

// Finalización del servidor
function exit() {
    // Limpieza
}

Capítulo 06

Consumir un Servidor MCP

Conexión desde un cliente, descubrimiento de capabilities.

1. Conexión desde un Cliente

Un cliente MCP debe implementar las siguientes funciones:

  • connect: Conexión al servidor MCP.
  • discover: Descubrimiento de capabilities del servidor.
  • call: Invocación de herramientas en el servidor.
Pseudocódigo Multi-SDK 
// Conexión al servidor MCP
function connect(serverUrl) {
    // Configuración de la conexión
    return new Client(serverUrl);
}

// Descubrimiento de capabilities
function discover(client) {
    return client.discover();
}

// Invocación de herramientas
function call(client, toolName, arguments) {
    return client.call(toolName, arguments);
}
